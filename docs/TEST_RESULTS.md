# Test results

Run on 19 Nov 2026. Generated by `scripts/test-report.py` from the actual runs; nothing here is typed by hand.

## What was run, and where

- **Database suite** (`scripts/db-test.sh`): PostgreSQL 16 with a local stub of Supabase's `auth` and `storage` schemas. All 20 migrations applied from empty, then the 12 business workflows, the security, automation and storage checks, the Phase 3 batches and a 20-villa synthetic resort lifecycle (labelled SYNTHETIC TEST DATA) executed as real users through the `api` functions under row-level security. Followed by a backup (`pg_dump`) and restore (`pg_restore`) into a fresh database with row counts compared.
- **Browser suite** (`tests/e2e/app_workflows.py`): headless Chrome driving the prototype screens — sign-in, clicks and form entry as different users — through the same 12 workflows, the negative cases and the Phase 3 screens (action center, digital twin, financial intelligence, contractor scores, procurement planning, executive reports, AI questions, mobile drafting).
- **Permission match** (`tests/consistency/permissions_match.py`): the prototype's role matrix compared grant by grant with the database defaults.
- **Production application** (`app/`): unit tests (`bun test`), TypeScript type check, production build, and a browser run (`app/tests/e2e/app_production.py`) of the built application against the real database through `app/dev/gateway.ts`, a LOCAL-ONLY stand-in for Supabase's PostgREST RPC and Auth endpoints (password sign-in, TOTP enrolment and verification raising the session to aal2).

## Not verified

- Nothing has been deployed: no hosted Supabase project, no Vercel deployment, no GitHub Actions run.
- Supabase-specific behaviour (PostgREST exposure of `api`, real Auth/MFA, Storage API limits, pg_cron) — the stub only imitates the parts the SQL depends on. pg_cron was not available locally, so the scheduler block was skipped.
- Email and WhatsApp delivery — no provider is connected; the tests only prove these are recorded as *not configured* and never as sent.
- The AI assistant with the live model — it runs only inside claude.ai after the viewer allows it; the tests cover the fallback when it is unavailable.
- The production application against hosted Supabase and Vercel: the staging project exists (19 Nov 2026) but the schema has not been pushed and nothing is deployed; the browser run used the local gateway, not real PostgREST or Supabase Auth.
- Hosted PostgreSQL is version 17; every run here used PostgreSQL 16.
- Performance on real data and real network: the timings in `docs/perf/` are on synthetic volume on the build machine.
- Offline capture on real phones and poor networks — the prototype keeps drafts on the device; no service worker exists.
